## 1. Readme

### 1-1. 무엇인가

- Co-Star 창업자 Banu Guler(CEO)와 Emily Segal(브랜드 총괄)이 만들었다.
- 2026년 9월 출시. iPhone 전용, iOS 26 이상. 18세 이상만 가입.
- 앱스토어 개발사 표기는 Co-Star Astrology Society.
- 홍보 문구: "읽는 사람, 쓰는 사람, 말하는 사람을 위한 소개팅", "서점에서 우연히 만나는 장면의 디지털 버전".
- 점성술은 "당분간" 소개팅 화면에 넣지 않는다고 Guler가 말했다.

### 1-2. 매칭 방식

- 가입하면 먼저 **25문항 퀴즈**를 푼다.
  - 대부분 **문장 두 개 중 더 좋은 쪽 고르기**다. 문학 인용문이 나온다.
  - 일부는 개인 질문이다. 예: "의외로 서툰 것은?"
  - 결과는 **12가지 독서 아키타입** 중 하나다. 문학, 언어 분석, 심리언어학 연구를 참고했다고 한다.
- 아키타입은 매칭 상대를 **거르지 않는다**. 매칭된 뒤에 보인다. 대신 "궁합 예측"에 쓴다고 Guler가 말했다.
- 프로필은 "인생 책 10권" 목록이 아니다. "언어 취향의 초상"을 만드는 것이 목표라고 Segal이 설명했다.
- **지금 읽는 책**을 공유하고, 다른 사람이 읽는 책을 본다.
- **지인 단계 필터**: 친구, 친구의 친구로 후보를 좁힐 수 있다.
- 화면 구조는 기존 앱과 비슷하다. 사진 넘기기, 짧은 기본 정보, 왼쪽(아니오)/오른쪽(예) 탭. (Bustle)

## 4. A) 📚 책 덕후방 기능 제안 (소개팅 아님)

### A1. 문장으로 보는 내 책 취향 테스트 (12유형 + 공유 카드)

- 아이디어: Readme의 "문장 두 개 중 고르기"를 연애 없이 쓴다.
- 화면
  1. 시작 화면: "문장 12쌍만 고르면 내 책 취향 유형이 나와요." 참여자 수 표시.
  2. 문항 화면: 문장 A / B 카드 두 장. 탭하면 다음으로. 진행 막대.
  3. 결과 화면: 유형 이름(예: "밑줄 수집가", "첫 장 탐험가"), 한 줄 설명, 어울리는 책 3권(기존 책 추천 카드 재사용), 유형 분포 막대("나와 같은 유형 14%").
  4. 공유 카드: OG 이미지 자동 생성. "나는 ○○형. 너는?" 링크.
  5. 결과 하단: "첫 문장 테스트도 해 보기", "책 덕후방 가기".
- 데이터
  - 문항: 12쌍. 문장은 저작권 만료 작품, 짧은 인용, 또는 운영자가 직접 쓴 문장으로 만든다. 출처는 표시.
  - 저장: 답 비트마스크(12비트) + 유형 + 방문자 쿠키 해시. 기존 first-line-test API 구조(mask, visitorHash, rate limit)를 그대로 따른다.
  - 개인 정보 없음. 닉네임 불필요.
- 왜 사람이 오고 남는가
  - 혼자 해도 1분 안에 끝난다. 결과 카드가 카톡·인스타로 퍼진다.
  - 유형별 "이번 주 추천 책"으로 다시 오게 한다.
  - 이미 있는 첫 문장 테스트와 서로 연결된다.
- 공수: **M** (문항·유형 기획이 대부분, 코드는 기존 테스트 재사용)

### A2. 내 책장 3권 카드 + 친구와 책 궁합 링크

- 아이디어: Hoppy의 "취향 스크랩북"을 책 3권으로 줄인다. 친구에게 링크를 보내 궁합을 본다.
- 화면
  1. "내 책장 3권 고르기": 책 검색(기존 books 데이터) 또는 제목 직접 입력. 각 책에 이유 한 줄(선택, 40자).
  2. 내 카드: 책 3권 표지 또는 제목 타일 + A1 유형(했다면) + 키워드 3개 자동("느린 문장", "SF", "에세이").
  3. "친구랑 궁합 보기" 버튼: 링크 생성(/book-match/토큰).
  4. 친구 화면: 친구도 3권을 고른다(가입 없음). 결과: 궁합 점수, 겹친 책·작가·장르, "서로에게 추천할 책 1권씩".
  5. 결과 공유 카드: "우리 책 궁합 78%".
- 데이터
  - match_card: 토큰(추측 불가 난수), 책 ID 3개, 이유 한 줄, 유형, 생성 시각. 30일 뒤 자동 삭제.
  - 친구 응답: 같은 형식. 두 카드를 합친 결과만 보여 준다.
  - 자유 입력 이유 한 줄은 연락처·URL 필터를 통과해야 저장.
- 왜 사람이 오고 남는가
  - "친구에게 보내야 결과가 나오는" 구조라 1명이 1명 이상을 데려온다.
  - 연인, 친구, 독서모임 모두 쓸 수 있다. 소개팅이 아니라 부담이 없다.
  - 결과의 "추천 책"이 책 덕후방 글로 이어진다.
- 공수: **M**

### A3. 첫 문장 블라인드 책 교환 (주간 라운드)

- 아이디어: 제목을 숨기고 첫 문장만으로 책을 고른다. "블라인드 북"을 온라인으로.
- 화면
  1. 올리기: 추천하고 싶은 책의 첫 문장(1~2문장) + 힌트 한 줄(장르, 분량). 제목은 숨김 필드로 입력.
  2. 고르기: 이번 주 첫 문장 카드 목록. 마음에 드는 카드 하나를 "뽑기".
  3. 공개: 뽑으면 제목·작가 공개. 한 줄 반응("읽어 볼게요", "이미 읽음") 남기기.
  4. 주간 결산: "가장 많이 뽑힌 첫 문장 TOP 5" 운영자 글(운영자 표기).
  5. 다음 주 알림(기존 push 사용, 선택).
- 데이터
  - blind_book: 첫 문장, 힌트, 제목, 작가, 올린 닉네임, 주차, 뽑힌 수.
  - 뽑기 기록: 방문자 해시 + 카드 ID (중복 방지).
  - 첫 문장은 짧은 인용만 허용(글자 수 상한, 예 120자). 저작권 인용 범위를 넘지 않게 한다.
- 왜 사람이 오고 남는가
  - 매주 새 라운드라 다시 올 이유가 생긴다.
  - 기존 첫 문장 테스트, 책 추천 카드와 같은 결이라 방 정체성이 강해진다.
  - 올린 사람은 "내 책이 몇 번 뽑혔나" 보러 돌아온다.
- 공수: **M** (S로 줄이려면 주간 결산을 수동 운영자 글로)

## 5. B) 💌 미혼남녀 만남 행사방 기능 제안 (안전하게)

### 공통 안전 원칙

- **19세 이상**만. 진입 시 "만 19세 이상입니다" 확인. 자기 확인만으로는 법적 연령 확인이 부족할 수 있다(아래 법률 항목).
- **연락처 교환 금지**(방 규칙 유지). 전화번호, 카카오 ID, 오픈채팅 링크, 인스타 계정, 이메일, URL을 정규식으로 막고, 막힌 시도는 기록.
- **1:1 채팅 없음**. 연결은 오프라인 행사 초대로만.
- **신고**: 모든 카드에 신고 버튼. 신고 누적 시 자동 숨김, 운영자 검토.
- **최소 수집**: 사진, 실명, 직장, 학교, 지역 상세를 받지 않는다. 성별, 연령대(5세 단위)만.
- **자동 삭제**: 행사 종료 후 7일 안에 프로필·관심 기록 삭제.
- **조작 금지**: 운영자가 만든 예시 카드는 "예시" 표기. 가짜 참여자, 가짜 후기 금지.
- 법률 검토 필요 항목 [법률 자문 전 확정 금지]
  - **개인정보보호법**: 성별·연령대·취향은 닉네임과 묶이면 개인정보가 될 수 있다. 수집 목적, 항목, 보유 기간을 화면에 알리고 동의를 받는다. 책 취향은 사상·신념(민감정보)을 짐작하게 할 수 있으니 자유 서술을 최소화하고 행사 목적 외 사용을 금지한다.
  - **결혼중개업의 관리에 관한 법률**: 개인과 개인을 결혼 목적으로 짝지어 주고 돈을 받으면 결혼중개업 신고·등록 대상이 될 수 있다. 1:1 매칭이 아니라 "같은 행사 초대"로 설계하고, 매칭 자체로 돈을 받지 않는다.
  - **청소년 보호(청소년보호법, 정보통신망법)**: 이성 만남을 주선하는 서비스는 청소년유해매체물 지정·성인 인증 의무 문제가 생길 수 있다. 가입 없는 구조와 충돌할 수 있으니 출시 전 반드시 확인한다.
  - 오프라인 행사 주최가 외부 업체라면, 노방장은 "정보 안내"임을 표시하고 업체 책임 범위를 분리한다.

### B1. 책 3권 블라인드 카드 + 서로 관심 시 "같은 행사 초대"

- 아이디어: Readme의 "취향으로 먼저 보기"만 가져온다. 얼굴·연락처·채팅은 없다.
- 대상: 방에 올라온 특정 오프라인 행사에 **참가 의사**가 있는 사람만.
- 화면
  1. 행사 상세에서 "책 카드로 미리 인사하기" 버튼. 19+ 확인, 개인정보 안내·동의.
  2. 카드 만들기: 좋아하는 책 3권 + 문장 고르기 3문항(A1 재사용) + 성별 + 연령대. 닉네임은 이 행사 전용 새 닉네임(방 닉네임과 분리).
  3. 카드 둘러보기: 같은 행사 카드만, 하루 최대 10장. 사진 없음. "관심" 버튼만.
  4. 서로 관심: 두 사람 모두에게 "○○ 님도 관심을 보냈어요. 행사장에서 만나요." 행사 날짜·장소 안내만. 연락처, 채팅 없음.
  5. 행사 당일: (선택) 서로 관심인 사람끼리 같은 책 키워드 이름표를 주최자가 준비.
  6. 행사 후 7일: 모두 삭제. "다음 행사" 안내만 남김.
- 데이터
  - event_card: 행사 ID, 행사 전용 닉네임, 성별, 연령대, 책 ID 3개, 답 3비트, 브라우저 PIN 해시, 생성 시각, 삭제 예정 시각.
  - interest: 보낸 카드, 받은 카드, 시각. 상대에게는 서로 관심일 때만 알림.
  - report: 카드 ID, 사유, 시각.
- 안전 규칙
  - 자유 입력 칸 없음(책 검색 선택 + 객관식만). 연락처를 적을 자리가 없다.
  - 한 브라우저 한 카드. PIN 분실 시 새 카드 불가(행사당).
  - 신고 2건이면 자동 숨김. 운영자 검토.
  - 관심을 받은 사실은 서로 관심일 때만 알린다(거절 노출 없음).
- 위험
  - 법률: 결혼중개업, 청소년 보호, 개인정보 문제. 법률 검토 없이는 출시하지 않는다.
  - 사람 수: Readme처럼 카드가 적으면 썰렁하다. 행사 참가 확정자가 일정 수(예 20명) 넘을 때만 열기.
  - 남녀 비율 불균형. 한쪽 성별 카드가 너무 적으면 둘러보기를 막고 "행사장에서 만나요" 안내만.
  - 행사장 밖에서 찾아내기: 닉네임이 행사 전용이라 위험은 낮지만, 행사 당일 안전 안내(주최자 연락처, 귀가 안내)를 함께 둔다.
- 공수: **L**

### B2. 행사 "책 취향 테이블" (개인 카드 없이 집계만)

- 아이디어: 개인 매칭 대신 행사 전체의 취향을 보여 준다. 위험이 훨씬 낮다. Hoppy의 회원 행사 + Readme의 책 대화 주제.
- 화면
  1. 행사 상세에 "이번 행사 책 취향" 섹션.
  2. 참가 예정자는 익명으로 책 1~3권과 문장 고르기 3문항 응답(19+ 확인, 저장 안내).
  3. 공개 화면: 개인 정보 없이 집계만. "참가자가 가장 많이 고른 책 TOP 5", "문장 취향 분포", "이번 행사 대화 주제 카드 5장".
  4. 행사 형식 제안: "책 한 권 들고 오는 소개팅" 회차. 주최자가 취향 집계로 테이블 주제를 정한다(예: SF 테이블, 에세이 테이블).
  5. 행사 후: "이번 행사 대화 주제" 운영자 정리 글(운영자 표기, 실제 집계만, 후기 조작 금지).
- 데이터
  - event_taste: 행사 ID, 방문자 해시, 책 ID 최대 3개, 답 3비트. 행사 종료 후 7일 삭제, 집계 수치만 보존.
  - 응답이 5명 미만이면 집계를 공개하지 않는다(개인 추정 방지).
- 안전 규칙
  - 개인 카드, 관심, 알림 없음. 사람을 고르는 기능이 없다.
  - 자유 입력 없음.
  - 테이블 배정을 하면 주최자에게 넘기는 정보는 "테이블 번호"뿐. 주최자에게 개인 응답 원본을 주지 않는다.
- 위험
  - 재미가 B1보다 약하다. 대신 기존 "오늘의 썸 카톡" 투표, 연애 성향 테스트와 묶으면 방 활동이 늘어난다.
  - 행사가 적은 시기에는 빈 섹션. 다음 행사가 없으면 숨긴다.
- 공수: **S~M**

## 6. 추천 순서

1. **A1 문장 취향 테스트** 먼저. 혼자 해도 재미있고, 공유 카드로 새 사람이 온다. 기존 첫 문장 테스트 코드를 재사용한다.
2. **A2 책 궁합 링크**. A1 유형을 그대로 쓰고, 친구 초대 구조로 퍼진다.
3. **B2 책 취향 테이블**. 미혼남녀방에 책 이야기를 안전하게 들인다. 개인 매칭이 없어 법적 위험이 낮다.
4. **A3 블라인드 교환**은 책방 재방문용으로 이어서.
5. **B1 블라인드 카드**는 법률 검토(결혼중개업, 청소년 보호, 개인정보)와 행사 참가자 수가 확보된 뒤에만.
