# 보안 재점검 기록 (Sprint 29)

Sprint 18(오픈 전 최종 점검) 이후 추가된 기능 — 라벨 사진 읽기(20)·규칙 투표(21·23)·리뉴얼 추적(25·26)·읽기 전용 모드(27)·라벨 변경 이력(28) — 을
공격자 관점에서 다시 읽고, 찾은 문제를 고쳤습니다. 영역별로 코드를 따로 읽어 점검하고, 발견마다 재현 테스트를 붙였습니다.

공통 원인: 이용자 식별값(fingerprint)은 HMAC(IP|User-Agent) 라서 **같은 IP 에서 User-Agent 만 바꾸면 새 사람처럼 보입니다.**
Sprint 9 에서 받아들인 한계였지만, 그 뒤 기능들이 "서로 다른 N명"·"사람마다 한도"에 기대면서 영향이 커졌습니다.
이번에는 결과가 공개되거나 비용이 드는 곳에 **접속 망 단위(IPv4 /24·IPv6 /48 의 HMAC, IP 로 되돌릴 수 없음)** 기준을 더했습니다.

## 그대로 둔 것 (판단 필요·수용)

- **규칙 투표 보류 만료**: 조작 의심 알림이 "심각"(탐지된 표가 결과를 가름)이어도 운영자가 3일 안에 처리하지 않으면 그 표를 포함해 마감됩니다. 무기한 보류는 운영자의 무대응이 곧 거부권이 되고, 자동 제외는 오탐을 규칙이 무효화하는 것이라 **운영 원칙상 사람이 정할 문제**로 남겼습니다 (PR 의 사람이 할 일).
- **규칙 투표 기록 보관**: 표의 식별값·계정 나이·기여 수는 공개 이력과 함께 보관됩니다(망 변환값만 30일 뒤 삭제). 마감 N일 뒤 식별값을 지우는 것은 재집계·이의 처리와 맞물려 다음으로 넘깁니다.
- **"AI 판독" 표시의 뜻**: 작성자가 올린 사진에서 AI 가 그 값을 읽었다는 뜻일 뿐, 사진 자체가 진짜인지·어느 제품 칸의 값인지까지 보장하지 않습니다(가짜 라벨·사진 속 지시문). 화면 문구는 "AI 판독 · 작성자 확인"으로 둡니다.
- **`/api/health` 공개 정보**: 마이그레이션 이름·가동 시간·배치 이름이 보입니다. 배포 확인(RUNBOOK 4장)과 외부 감시에 쓰므로 유지합니다. 오류 원문은 내보내지 않습니다.
- **식별값 모델 자체**: 여러 망(집 Wi-Fi + 휴대폰 데이터)을 쓰는 사람은 여전히 여러 명으로 보일 수 있습니다. 가입 없는 구조의 한계이며, 결과가 공개되는 판단(리뉴얼·규칙)은 망 기준·계정 나이·탐지·공개 기록을 겹쳐 비용을 높이는 방식입니다.
